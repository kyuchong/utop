# N2X 연결 — 210.1.2.248 (윈도우)

## 왜 이게 필요한가

N2X(RouterTester 900) Tcl API 는 `C:/N2xTcl85` 의 **윈도우 네이티브 DLL** 이다.
리눅스에는 이 DLL 이 없다 — 파이썬으로 감싸도 못 부른다. 그래서 N2X 명령은
반드시 **N2X 가 깔린 윈도우 기계에서** 나가야 한다.

```
리눅스 백엔드(213)  ──HTTP 5099──▶  210.1.2.248 (윈도우)
                                     └─ n2x_relay.py ─▶ n2xtclsh85 ─▶ 섀시
```

## 지금 상태 (리눅스에서 본 것)

- 210.1.2.248 **살아 있음** (ping 0.26ms, 같은 랩망)
- 열린 포트: **3389(RDP) · 445(SMB) · 5900(VNC)** 뿐
- **N2X 서버·중계는 안 떠 있음** — 그래서 아직 붙을 곳이 없다

리눅스에서 할 수 있는 것은 여기까지다. N2X DLL 이 윈도우 전용이라, 중계를
그 윈도우에서 띄우는 것은 **그 기계에 들어갈 수 있는 사람**만 할 수 있다.

## 한 번만 하면 되는 것 (윈도우에서)

**1. 중계 파일을 N2X 기계에 둔다.**
   저장소의 `tools/n2x_relay.py` 와 `backend/n2x/*.tcl` 을 한 폴더에 복사한다.
   (예: `C:\utop-n2x\`)

**2. 파이썬이 있는지 본다.** `python --version`. 없으면
   [python.org](https://www.python.org/downloads/windows/) 에서 설치.
   **추가 라이브러리는 없다** — 표준 라이브러리만 쓴다.

**3. 열쇠를 정하고 띄운다.**
   ```
   cd C:\utop-n2x
   set N2X_RELAY_KEY=아무-긴-문자열-하나
   python n2x_relay.py
   ```
   콘솔에 `n2xtclsh : ... (있음)` 이 나오면 N2X 가 제대로 깔린 것이다.
   `(없음!)` 이면 N2X 소프트웨어부터 확인한다(`N2X_TCLSH` 로 경로 지정 가능).

**4. 방화벽에서 5099 를 연다** (인바운드 TCP).

## 리눅스(213)에서

`.env` 에 두 줄을 넣는다 (열쇠는 위와 **같은 값**):

```
N2X_RELAY_URL=http://210.1.2.248:5099
N2X_RELAY_KEY=아무-긴-문자열-하나
```

api 를 다시 띄운다:

```
cd ~/utop && docker compose up -d api
```

## 붙었는지 확인

윈도우 중계 콘솔에서:
```
curl -X POST http://localhost:5099/api/n2x/send ^
  -H "Content-Type: application/json" ^
  -d "{\"cmd\":\"ping\",\"server\":\"210.1.2.248\",\"key\":\"...\"}"
```
`{"ok": true, "session": ...}` 이면 섀시까지 붙은 것이다.

리눅스에서:
```
curl "http://localhost:9000/api/n2x/ping?server=210.1.2.248"
```

## 왜 자동으로 못 해 두나

중계를 띄우는 것은 그 윈도우 기계에 **RDP 로 로그인**해서 해야 한다.
남의 계정으로 로그인하거나 비밀번호를 대신 넣는 일은 하지 않는다 —
그건 사람이 한다. 파일과 명령은 위에 다 있으니 로그인 뒤 3·4번만 하면 된다.

## 중계는 검증됨

`tools/n2x_relay.py` 는 리눅스에서 가짜 데몬으로 끝에서 끝까지 확인했다 —
HTTP · 열쇠 검사(403/200) · 데몬 수명관리 · ping·ports·tstart·tstat·tstop
왕복. 진짜 N2X 가 깔린 윈도우에 놓으면 그대로 돈다.
