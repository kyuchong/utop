# N2X 중계 설치 — 210.1.2.248 (윈도우)

리눅스 실행 서버(253)에서 N2X 를 쓰기 위한 중계 설정. **다음에 회사에서
이 문서만 보고 따라 할 수 있게** 적는다.

## 왜 필요한가

계측기 둘의 처지가 다르다.

| | 붙는 방식 | 리눅스에서 되나 |
|---|---|---|
| **STC** (192.168.5.100) | REST 서버에 HTTP. 서버 주소를 **네트워크 너머로** 가리킬 수 있다 | **된다** — 중계 불필요 |
| **N2X** (210.1.2.248) | 백엔드가 있는 **그 기계에서** N2X Tcl 프로세스를 띄운다 | **안 된다** |

N2X 는 네트워크 너머의 윈도우를 못 쓴다. 그래서 그 윈도우에 백엔드를
하나 더 띄우고 N2X 명령만 넘긴다. 시험은 253 이 돌리고 Tcl 만 건너간다.

```
253 (리눅스, 실행 서버)
 ├─ STC   ──HTTP 8888──▶  192.168.5.100        서버+섀시 통합
 └─ N2X   ──HTTP 8000──▶  210.1.2.248 (윈도우)  ──▶ N2X Tcl ──▶ 섀시
                          중계 전용 백엔드
```

## 1. 210.1.2.248 에서 — 중계 띄우기

DB 도 도커도 필요 없다. 파이썬과 소스만 있으면 된다.

```
git clone <저장소> C:\utop
cd C:\utop
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

환경변수를 넣고 띄운다. `N2X_RELAY_KEY` 는 아무 긴 문자열이면 되고,
253 에 넣을 값과 **한 글자도 다르면 안 된다.**

```
set N2X_RELAY_ONLY=1
set N2X_RELAY_KEY=여기에-긴-문자열
python -m uvicorn backend.main:app --host 0.0.0.0 --port 8000
```

기동 로그에 이 줄이 보여야 한다.

```
[startup] N2X 중계 전용 — DB 를 잡지 않습니다
```

### N2X Tcl 경로가 다르면

기본값은 `C:\N2xTcl85\bin\n2xtclsh85.exe` 다. 이 기계의 설치 위치가
다르면(`C:\Program Files\Agilent\N2X\bin\...` 인 경우도 있다) 환경변수로
알려준다.

```
set N2X_TCLSH=C:\실제\경로\n2xtclsh85.exe
```

경로가 틀리면 오류가 **찾은 경로와 이 서버의 OS 를 그대로 적어 준다** —
그걸 보고 고치면 된다.

## 2. 그 자리에서 확인

같은 PC 에서:

```
curl -X POST http://localhost:8000/api/n2x/send -H "Content-Type: application/json" -d "{\"cmd\":\"ping\",\"key\":\"위에-넣은-문자열\",\"server\":\"210.1.2.248\"}"
```

- `{"ok":true,...}` — 됐다. 3번으로
- `N2X Tcl 이 이 서버에 없습니다 — 찾은 곳: …` — `N2X_TCLSH` 를 고친다
- `중계 열쇠가 다릅니다` — 열쇠 오타
- `이 서버는 중계로 열려 있지 않습니다` — `N2X_RELAY_KEY` 를 안 넣었다

## 3. 253 에서 — 중계를 가리키게

`.env` 에 두 줄을 넣고 다시 띄운다.

```
N2X_RELAY_URL=http://210.1.2.248:8000
N2X_RELAY_KEY=1번에서-넣은-것과-똑같이
```

```
docker compose -p utop --env-file .env up -d --build api
```

253 에서 확인:

```
curl -s -m 20 http://210.1.2.248:8000/api/health
```

그다음 UTOP 화면에서 **계측기 → 210.1.2.248 → 연결 확인**, 또는 TC 의
**토폴로지 탭 → 불러오기** 로 포트 목록이 오면 끝이다.

## 4. STC 는 따로 할 것이 없다

192.168.5.100 이 서버와 섀시를 겸하므로, 계측기 등록에서

- **IP** (섀시) — `192.168.5.100`
- **STC (REST)** 를 켜고 **REST 서버 IP** — `192.168.5.100`, 포트 `8888`

253 에서 미리 확인해 볼 수 있다.

```
curl -s -m 5 -o /dev/null -w "%{http_code}\n" http://192.168.5.100:8888/
```

응답이 오면 그대로 쓰면 되고, 안 오면 그 기계에서 `stcweb.exe`(Spirent
TestCenter Application 폴더)를 먼저 띄워야 한다.

## 안전장치

중계 창구(`/api/n2x/send`)는 서버끼리 부르는 자리라 사람의 로그인 세션이
없다. 그래서 로그인 검사에서 빼는 대신 `N2X_RELAY_KEY` 로 자기가 확인하고,
**열쇠를 안 정해 두면 아예 거절한다.** 안 열린 채로 두는 것이 기본이다.

중계 전용으로 뜬 서버는 `/api/n2x/*` 와 `/api/health` 말고는 전부 503 이다.
자료가 없는 서버가 시험 화면인 척하면 알 수 없는 오류만 보게 된다.

## 되돌리기

실행 PC 를 다시 윈도우로 옮기게 되면 `N2X_RELAY_URL` 만 지우면 된다.
비어 있으면 예전처럼 그 기계에서 직접 Tcl 을 띄운다 — 코드는 그대로다.
