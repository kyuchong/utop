# 서버 실행 (사이클)

실행을 브라우저가 붙들고 있었다. 64건을 걸어 놓고 탭을 닫으면 거기서
멈췄고, 자리를 뜰 수가 없었다. 실행 서버를 따로 둔 의미도 없었다.

이제 화면은 **일감을 줄에 걸고 손을 뗀다.** 실행기가 집어서 돌린다.

```
화면 ──POST /api/runs──▶ api ──cycle_run 표──▶ 실행기(runner)
                          ▲                        │
                          └── 진행·로그 ───────────┘
                          │
                          └── WebSocket ──▶ 보고 있는 사람들 화면
```

## 왜 판정기를 파이썬으로 안 옮겼나

판정·변수·표 판정 규칙은 `web/src/components/tc/judge.ts` 와 `runner.ts` 에
있다. 백엔드 `engine.py` 에도 옛 판정기가 남아 있지만 `ok`·`table` 같은
지금 규칙을 모른다.

두 벌이면 규칙을 고칠 때마다 양쪽을 맞춰야 하고, 어긋나는 순간 **같은
시험이 TC 화면에서는 Pass, 사이클에서는 Fail** 이 된다.

그래서 실행기는 **같은 TypeScript 를 Node 로 묶어** 돈다. `runner/build.mjs`
가 `web/src` 를 그대로 가져다 쓰고, 브라우저와의 차이는 `runner/src/api.ts`
하나뿐이다 — API 주소를 붙여 부르는 것.

## 띄우기

`.env` 에 열쇠가 있어야 한다. 없으면 대기줄이 아예 안 열린다.

```
RUNNER_KEY=<아무 긴 문자열>
```

```bash
docker compose up -d --build api runner
```

## 실행 서버를 253 에 따로 둘 때

실행기는 장비에 직접 안 붙는다 — API 를 통해 붙는다. 그래서 실행기만
따로 띄우고 API 주소만 향하게 하면 된다.

```bash
# 253 에서
RUNNER_API_BASE=http://220.1.1.213:8000 RUNNER_NAME=253 \
  docker compose up -d --build runner
```

여러 대를 띄워도 된다. 일감은 `FOR UPDATE SKIP LOCKED` 로 집으므로 같은
것을 둘이 집지 않는다.

단, API 가 213 에서 포트를 안 열고 있다면(기본값이 그렇다) 열어 주거나
같은 도커망에 두어야 한다.

## 알아둘 것

- **한 사이클에 하나씩.** 같은 사이클을 둘이 동시에 돌리면 결과를 서로
  덮는다. 이미 돌고 있으면 409 로 막고 누가 돌리는지 알려준다.
- **멈춤은 부탁이다.** 그 자리에서 죽이지 않는다 — 실행기가 스텝 사이에서
  보고 스스로 내려와야 장비 세션이 열린 채로 남지 않는다.
- **죽은 실행은 3분 뒤 걷힌다.** 실행기가 죽거나 서버가 내려가면
  `running` 인 채로 영원히 남아서, 화면은 계속 도는 줄 알고 기다리고 다시
  돌릴 수도 없게 된다. 신호(`heartbeat_at`)가 끊긴 지 오래면 실패로 내린다.
- **로그는 서버가 들고 있다.** 창을 닫았다 다시 열면 처음부터 다 받아
  그대로 다시 그린다.
