# Cycles — 사이클·실행·판정·결과

## 무엇을 하는 화면인가

시험 항목을 묶어 **한 번의 시험(사이클)** 으로 만들고, 장비에 돌리고, 합격·불합격을 모으고, 결과 메일과 결과서(PPTX·PDF)를 낸다.
실행은 브라우저가 아니라 **실행기(runner) 컨테이너**가 한다. 걸어 놓고 탭을 닫아도 돈다.

## 어디 있나

왼쪽 메뉴 QUALITY › **Cycles**. 왼쪽은 사이클 폴더와 목록, 가운데는 고른 사이클의 시험 항목, 오른쪽은 상세·실행·결과 탭이다.
옛 Runs·Reports 화면은 이 안으로 합쳐졌다. 옛 주소(`?p=runs`)로 들어오면 여기로 온다.

## 하는 일

### 사이클 만들기
- 「+ 사이클」. 사업자·모델그룹·모델·버전·버전그룹·담당을 적는다. ID 는 `C0001` 꼴로 서버가 매긴다.
- 「항목 추가」 로 REQ-Coverage 의 시험 항목을 고른다. 폴더째 넣을 수 있다. 사이클에 넣은 항목은 그 시점의 스텝을 복사해 갖는다.
- 시험 조건(실험실·장비 배치)을 적어 두면 결과서에 실린다.

### 실행
- 항목을 고르고 「실행」. 실행 종류는 **자동**(장비에 스텝을 보낸다)과 **수동**(사람이 결과를 찍는다)이다. 항목마다 종류가 있다.
- 실행하면 **회차**가 하나 생긴다(`RUN_E0001` 꼴). 「다시 실행」 은 지난 회차를 덮지 않고 다음 번호로 쌓인다.
  실행 건수는 「건」, 회차는 「회」 로 말한다 — 100회 돌린 것이 1회로 읽히지 않게.
- 반복 시험: 고른 묶음을 몇 바퀴 돌지, 회차 사이 쉬는 시간, 실패하면 계속·멈춤·종료 중 무엇을 할지 정한다.
- 실행기는 항목의 장비가 다르면 여러 건을 동시에 돈다(기본 4건). 같은 장비는 **자원 잠금**으로 한 번에 한 건만 붙는다.
  누가 어느 장비를 잡고 있는지 화면에 보이고, 사이클을 지우면 잠금도 풀린다.
- 진행은 회차마다 한 줄씩 실시간으로 올라온다. 「멈추기」 로 대기줄에서 뺀다.
- **셀 세션**: 스텝에 「셀 진입」 이 있으면 암호를 넣고 리눅스 셀로 들어가 다음 명령을 그 안에서 친다. reload 뒤 다음 스텝이 바로 답하지 않게 기다린다.

### 판정
- 스텝마다 응답과 판정 근거가 남는다. 근거는 「있다/없다」 가 아니라 **어느 줄에서 걸렸나**를 적는다.
- 항목의 판정은 스텝 판정을 모은 것이다. 기준이 없는 스텝은 판정하지 않고, 실행 자체가 안 된 스텝은 불합격이다.
- 수동 항목은 사람이 결과를 찍는다. 자동으로 다시 돌면 사람이 찍은 것은 지워진다.
- 판정 규칙은 REQ-Coverage 화면과 실행기가 **같은 코드**를 쓴다. 규칙의 정답표는 `web/src/components/tc/judge.test.ts` 에 있다.

### 결과
- **판정 현황** 막대와 진행률, 실패 항목만 보기, 회차끼리 비교(회귀).
- 항목 표의 **실행 횟수** 열은 이 사이클의 모든 실행에서 돈 회차의 합이다. 회차 기록이 없는 옛 실행과 수동 판정은 1회로 센다. 시험이 도는 동안은 4초마다 따라온다.
- 요약의 **일자별 실행 횟수** 그림은 회차의 시각(한국 시각)으로 날짜를 잡아 자동·수동으로 나눠 **그날 돈 수**를 보인다(누적 아님). 1000회 돌린 날은 1000, 안 돈 날은 0 이다. 진행률은 도넛이 말한다.
- **결함 걸기** — 실패 항목에서 「이슈 생성」 을 누르면 결함이 하나 만들어진다. 바로 Jira 로 안 가고 Defects 화면에 모인다([jira-defects.md](jira-defects.md)).
- **결과 메일** — 받는 사람·본문을 미리 보고 보낸다. 보낸 기록이 남는다. 실패 항목 요약과 링크가 들어간다.
- **결과서** — 고객사 양식 PPTX 로 굽는다(LG유플러스 양식 등). 화면에서 미리 보고 PPTX·PDF 로 받는다. 배율은 맞춤값의 90% 다.
- **AI 요약** — 등록된 LLM 이 있으면 회차 결과를 문장으로 요약한다.
- **집계** — 폴더 한 층의 현황(사업자·모델그룹·버전별 합격률)을 서버가 세어 준다. CSV 로 받는다.

## 규칙과 주의

- 실행기가 뜨려면 `.env` 의 `RUNNER_KEY` 가 있어야 한다. 비어 있으면 대기줄이 열리지 않아 사이클을 돌릴 수 없다.
- 실행 서버를 다른 PC(253)에 두려면 runner 서비스만 거기서 띄우고 `RUNNER_API_BASE` 를 시험 서버로 향하게 한다([../RUN_SERVER.md](../RUN_SERVER.md)).
- 화면 녹화를 켜면 브라우저 시계 값이 크게 부풀린다. 성능 수치는 녹화를 끄고 본다.
- 사이클 화면과 시험 항목 직접 실행 화면은 부품이 다르다. 사이클의 것을 고쳤다고 직접 실행 화면이 같이 바뀌지 않는다.

## 관리자가 할 일

- `.env` 의 `RUNNER_KEY`, 필요하면 `RUNNER_JOBS`(동시 실행 수). SETUP › **메일 설정**(결과 메일). SETUP › **실행 판정 기준**.
- 결과서 양식은 `backend/templates/pptx/` 에 둔다.

## 동작 확인

```bash
./tools/smoke.sh cycle
```

대본 `tests/smoke/cycle_smoke.py`: 사이클 저장·읽기·고른 항목·시험 조건 → 요약 본문·메일 미리보기·메일 기록 →
AI 요약·자동 Jira 는 LLM·Jira 없을 때 안내로 답하는가 → 집계·리포트·버전그룹·폴더 → 항목이 든 사이클·마지막 결과·실행 중 목록·실행 이력 →
플랜 실행(회차) 만들기·항목 결과 기록·통계·회차·지우기 → 대기줄에 걸기, runner 열쇠 없으면 거절하는가 → 진행 보고·멈추기 →
잠금 잡기·심장박동·한꺼번에·풀기 → CLI·셀 세션·ping·SNMP·trap 이 장비 없을 때 500 대신 안내인가 → 옛 절차·결과·PPTX 양식 → 지우기. 60개.

실제 장비 실행은 이 대본이 못 본다. 새 판을 올린 뒤에는 **사이클 하나를 짧게 돌려** 진행 표시와 판정이 나오는지 눈으로 본다.
