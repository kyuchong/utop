# 로그인 · SETUP — 계정·조직·권한·브랜딩·메일·데이터

## 무엇을 하는 화면인가

누가 들어오고(로그인·계정), 누가 무엇을 볼 수 있고(권한), 화면이 어떻게 보이고(브랜딩·보기), 결과가 어디로 가는지(메일·공유)를 정한다.
데이터를 묶음 단위로 내보내고 들여올 수 있다.

## 어디 있나

로그인 화면, 왼쪽 메뉴 **SETUP**, 오른쪽 위 내 이름(내 정보·암호·아바타). SETUP 의 하위 메뉴: LLM 설정 · 용도별 프롬프트 · 실행 판정 기준 ·
Jira 연동 · Jira 프로젝트 패널 설정 · 메일 설정 · 계정 관리 · 페이지별 접근 권한 · 데이터 내보내기 · 데이터 가져오기 · ID 옮기기 · 브랜딩 · 로그인 화면.

## 하는 일

### 로그인·세션
- 아이디·암호로 들어온다. **Jira 계정 로그인**을 켜 두면 Jira 가 확인하고, 처음 온 사람은 계정이 자동으로 만들어진다. 로컬 계정(admin 등)은 안전망이다.
- 세션은 30일 유지되고 서버가 다시 떠도 남는다(DB). 틀린 암호가 이어지면 잠시 잠근다.
- 모든 `/api/*` 는 로그인이 없으면 401 이다. 예외는 로그인·health·브랜딩(로그인 화면용)·실행기·N2X 중계뿐이다.

### 계정 관리 (관리자)
- 계정 만들기·고치기·잠그기·지우기. 역할은 관리자·사용자. 「사용자 동기화」 는 Jira 사용자를 받아 계정을 만들고 퇴사자를 잠근다.
  「퇴사자 정리」 로 잠긴 계정을 한 번에 지운다. 지난번 Jira 가 거절한 로그인은 여기서만 본다(아이디와 까닭, 암호는 없다).
- **조직도** — 부서 나무를 만들고 사람을 옮긴다. 조직 선택지(사업자·팀)는 화면 곳곳의 담당 칸에 쓰인다.

### 페이지별 접근 권한 (관리자)
- 역할·사람별로 어느 메뉴를 볼 수 있는지 표로 켠다. 관리자 키는 늘 전부다.

### 브랜딩·로그인 화면 (관리자)
- 회사 이름·로고·로그인 화면 사진과 로고. 로그인 전에도 보여야 해서 이 값만 공개다.

### 메일·공유 (관리자)
- SMTP 서버·보내는 사람·기본 받는 사람. 「시험 발송」 으로 한 통 보내 본다. 결과 메일·승인 미리보기 틀이 여기 것을 쓴다.
- 공유 설정: 주소 공유 시 기본 문구·받는 사람 묶음.

### 보기(View)와 설정값
- 표의 열·필터·정렬을 **보기 탭**으로 저장한다. 개인 보기는 스무 개, 공용 보기는 열두 개까지이고 공용 승격은 관리자만 한다.
  기본 탭과 보기 탭은 필터가 따로다.
- 화면 설정(마지막 본 화면·열 폭 등)은 **서버에 계정별**로 저장된다. 다른 PC 에서 로그인해도 따라온다. 로그아웃하면 다음 계정에 새지 않게 비운다.
- 새 판이 올라오면 화면 위에 「새로 고치기」 띠가 뜬다. 옛 판과 새 판이 다른 수를 보이는 일을 막는다.

### 알림·게시판·할일·감사
- 알림 종: 나를 멘션한 글, 사이클 완료 같은 소식. 수정 이력(감사)은 누가 무엇을 언제 바꿨나.
- 게시판(수정 요청)·할일·도움말·리소스(인력·프로젝트)는 **옛 UI** 에 남아 있다. api 컨테이너의 `/` 로 열린다.

### 버전 · 라이선스 (관리자)
- 왼쪽 메뉴 SYSTEM 바로 위에 **도움말**이 있다. 누구나 읽는다. WIKI 와 같은 편집기·표·지난 판·PDF 를 쓰고, 일반 위키 나무와는 섞이지 않는다.
  처음 실린 글은 기능별 문서이고, 관리자와 **페이지별 접근 권한**에서 「도움말 · 고치기」 를 받은 역할이 앱 안에서 고친다(권한 체계가 꺼져 있으면 관리자만).
  「처음 글로 되돌리기」 가 그 편을 처음 글로 되돌린다(지금 글은 지난 판으로 남는다).
- 도움말 위에 **판(버전·커밋)과 라이선스 기간**이 선다. 화면은 버전·라이선스·도움말 세 카드다. 버전은 저장소의 VERSION 파일, 커밋은 빌드 때 박힌다.
- **라이선스는 파일을 등록하고 상태를 본다.** 발급처가 서명한 `.lic` 파일을 올리면 서버가 Ed25519 서명을 확인하고 사용처·기간·남은 날수·사용 막대·발급 ID·등록 기록을 보인다.
  손으로 적는 칸은 없다. 서명이 틀리거나 고쳐진 파일은 까닭과 함께 거절된다. 상태는 유효·만료 임박(30일)·만료됨·시작 전·미등록이고 왼쪽 배지도 같은 색이다.
  발급은 `tools/license_issue.py`(개인키는 저장소 밖 `~/.utop-license/private.pem`, 공개키는 `backend/licensing.py`). Jira Data Center·GitLab EE·SonarQube 의 방식을 따랐다.

### 데이터 내보내기·가져오기 (관리자)
- 묶음(WIKI·요구사항·시험·사이클·결함·장비·설정)을 골라 JSON 한 통으로 내보내고, 다른 서버에서 들인다. 같은 ID 는 덮어쓴다.
- **ID 옮기기** — 옛 ID 를 모델그룹 기준으로 바꾸는 계획을 보고 적용한다([req-coverage.md](req-coverage.md)).

## 규칙과 주의

- `.env` 의 `POSTGRES_PASSWORD` 하나가 필수다. `RUNNER_KEY` 가 없으면 사이클을 돌릴 수 없다([cycles.md](cycles.md)).
- 도커 볼륨 둘(`db-data`·`app-data`)이 곧 데이터다. 백업은 [../backup.md](../backup.md).
- 백엔드 포트는 기본으로 호스트에 열지 않는다. 디버깅 때만 127.0.0.1 로 잠깐 연다.

## 관리자가 할 일

- 첫 기동 뒤 admin 암호 바꾸기 → 브랜딩 → Jira 연동(계정 로그인) → 계정 동기화 → 권한표 → 메일 설정 → LLM 설정.

## 동작 확인

```bash
./tools/smoke.sh settings
```

대본 `tests/smoke/settings_smoke.py`: 틀린 암호 401 → 로그인·내 정보 → health·브랜딩은 로그인 없이 → 계정 만들기·고치기·새 계정으로 로그인·암호 바꾸기·로그아웃 →
이름표·멘션 후보 → 조직도·노드 추가·선택지 → 메일 설정·보내기 시험(서버 없음 안내)·공유·권한·UI 옵션·전역 파라미터·도움말 →
내 보기 설정 저장·보기 탭 저장 → 알림·수정 이력·게시판·할일·대시보드·상태·접속자·데이터 내보내기 → 판·라이선스 파일 거절·해제 →
도움말 씨앗 7편(위키 공간, 블록노트 블록)·일반 위키에 안 섞임·고치기·처음 글로·새 문서·권한표의 「도움말 · 고치기」 로 팀원이 고치고 빼면 403, 읽기는 누구나 → 계정 지우기. 50개 안팎.
