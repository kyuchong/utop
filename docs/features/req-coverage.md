# REQ-Coverage — 요구사항과 시험 항목

## 무엇을 하는 화면인가

**무엇을 시험해야 하나(요구사항)** 와 **어떻게 시험하나(시험 항목, TC)** 를 한 화면에서 다룬다. 요구사항 하나에 시험 항목이 여럿 달린다.
분류 폴더(사업자 › 제품 › 갈래 › 세부, 최대 4단)로 나누고, 시험 항목에는 장비에 보낼 명령과 합격 기준을 스텝으로 적는다.
여기서 만든 시험 항목을 Cycles 에서 골라 돌린다.

## 어디 있나

왼쪽 메뉴 QUALITY › **REQ-Coverage**. 왼쪽 분류 나무, 가운데 요구사항·시험 항목 표, 오른쪽 상세(INFO)다.
표 위 **보기 탭**으로 열·필터·정렬을 저장해 두고 바꿔 가며 본다. 보기는 계정을 따라다니고, 개인 보기는 스무 개까지,
공용 보기는 관리자만 만들며 열두 개까지다.

## 하는 일

### 분류 폴더
- 나무에서 「+」 로 폴더를 만든다. 첫 단은 사업자(프로젝트), 그 아래 제품·갈래·세부다. 끌어다 놓아 옮긴다.
- 아래에 요구사항이나 폴더가 있으면 지울 수 없다.

### 요구사항
- 「+ 요구사항」. ID 는 모델그룹 기준으로 서버가 매긴다(예 `E6100-R0001`). 제목·구현 내용·시험 목적·사전 준비 같은 칸을 채운다.
- 본문 칸은 위키와 같은 편집기다. `/` 메뉴 차례도 위키와 같다.
- 구현 내용에 워드·PDF·엑셀 파일을 끌어다 놓으면 글로 풀어 넣는다.
- 요구사항을 고르면 오른쪽에 달린 시험 항목이 보인다. 「Map」 으로 있는 시험 항목을 붙이거나 뗀다.

### 시험 항목
- 「+ 시험 항목」. 신규와 Clone 은 **모델그룹·모델명이 필수**다(항목별로 모델이 고정된다). ID 예 `E6100-T0001`.
- **스텝** — 한 줄이 장비에 보낼 한 동작이다. 종류: CLI 명령, 셀 진입, SNMP get/set/trap, ping, 계측기(STC·N2X), 기다리기,
  반복(for)·조건(if), 값 견주기(Diff), 사람이 할 일(수동). 들여쓰기가 반복·조건 블록의 경계다.
- **판정** — 스텝마다 「어떻게 봐야 합격인가」 를 정한다. 두 방식이 있다.
  - **칩**(권장): 「있어야 …」·「없어야 …」·「줄에 있어야 …」·「줄 수 …」·「표에서 …」 칩을 여러 개 단다. 모두 맞아야 합격이 기본이고
    「하나만 맞아도」 로 바꿀 수 있다. 「⏱시각줄」·「줄제외」 칩으로 매번 바뀌는 줄을 빼고 본다.
  - **옛 방식**: 종류(출력에 있으면 합격 · 모두 있으면 · 있으면 불합격 · 오류만 없으면 · 항목 일치 · 표)와 기대값 한 줄.
    콤마는 「둘 중 하나」, 대소문자는 가리지 않는다.
  - 어느 쪽이든 장비가 `% Invalid input`·`Unknown command` 같은 오류로 답하면 기준을 볼 것도 없이 불합격이다.
- **변수** — 응답에서 정규식으로 값을 뽑아 `${이름}` 에 담고, 다음 스텝의 명령이나 기준에 쓴다. Diff 스텝은 변수끼리 견준다.
- **판정 영역**(Query) — 응답의 일부만 잘라 보게 한다. 표가 길 때 쓴다.
- **여러 줄 복제** — 스텝을 여러 줄 골라 「복제」 하면 마지막 고른 줄 아래에 연속으로 들어간다.
- **판 이력·스냅샷** — 저장할 때마다 판이 남는다. 오른쪽 상세에서 지난 판을 보고 되돌린다.
- **직접 실행** — 상세에서 「실행」 을 누르면 이 항목만 장비에 돌려 본다. 결과는 「실행 이력」 에 남고, 사이클에는 안 들어간다.

### 그 밖에
- **복제**(copy-tree) — 폴더·요구사항·시험 항목을 골라 다른 폴더로 통째로 베낀다. 모델을 바꾸면서 베낄 수 있다.
- **엑셀 내보내기** — 표에서 보이는 열·차례·색 그대로 .xlsx 로 받는다.
- **휴지통** — 지운 요구사항·시험 항목은 휴지통에 간다. 되살리거나 비운다.
- **ID 옮기기** — 옛 ID(`REQ-2632-0002` 꼴)를 모델그룹 기준 새 ID 로 바꾼다. 옛 주소로 들어오면 새 ID 로 넘겨 준다.
- **링크** — `?req=ID` · `?tc=ID` · `?cat=폴더ID` 주소로 그 자리가 바로 열린다.

## 규칙과 주의

- 시험 항목의 모델은 항목마다 고정이다. 공용 시험 항목을 두고 여러 모델에 돌리는 방식은 쓰지 않는다.
- 판정 규칙은 화면과 실행기(runner)가 **같은 코드** 를 쓴다. 화면에서 「이 응답이면 합격」 이었으면 실행기도 같다.
- 표 안에서 바로 고칠 때 줄은 제자리를 지키고, 바뀐 것이 없으면 저장하지 않는다.
- INFO 의 칸 색·폭은 SETUP 의 필드 설정이 정본이다.

## 관리자가 할 일

- SETUP › **코드표**: 심각도·상태 같은 선택지와 색. SETUP › **사용자 정의 필드**: 요구사항·시험 항목·플랜에 칸을 더한다.
- SETUP › **실행 판정 기준**: 판정 종류의 이름과 설명.

## 동작 확인

```bash
./tools/smoke.sh tc_req
```

대본 `tests/smoke/tc_req_smoke.py`: 분류 폴더 만들기 → 코드표·사용자 정의 필드 → 다음 ID 받기 → 요구사항 저장·목록·읽기 →
시험 항목 저장·목록·읽기·경로·고치기 → 판 이력·스냅샷이 생겼나 → 복제·엑셀 내보내기·옛 ID 찾기·ID 옮기기 계획이 500 이 아닌가 →
그림 올리고 그 주소로 다시 받는가 → 지우면 휴지통에 가고, 되살리고, 비우는가 → 요구사항·필드·분류 지우기. 40개.
